# Ева — бот-помощник сервера Aetherlyn (@RM_AI23bot)

ИИ-помощник Minecraft-сервера Aetherlyn в Telegram. Отвечает на вопросы игроков
по серверу и игре, знает **все плагины и датапаки** сервера, а также кастомные
плагины **«Разлом»**, **«Свадьба»** и **«Скорбь»** — их команды, механики и крафты.
Пишет плавно, «печатая» ответ на глазах у человека.

Версия кода: **6.5**.

## Что умеет

**Помогает по серверу.** Адреса и версии (Java и Bedrock), вход и анкета, правила,
онлайн, донат, ресурс-пак, чат и каналы — из карточки сервера, без выдумок.
Статус проверяется по живым адресам, а не по устаревшим значениям.

**Знает плагины для игроков.** `/plugins` — только те плагины, которыми реально
пользуются игроки (11 штук): телепорты, дом/варпы, квесты, ПвП по согласию,
регистрация, скины, голосовой чат, могилы, «Разлом», «Свадьба», «Скорбь».
Служебные и админские плагины (CoreProtect, LuckPerms, ProtocolLib, Chunky,
spark, bStats и т.д.) в список не попадают — но Ева про них знает и ответит,
если спросить. `/plugins разлом` — подробно про конкретный плагин.
`.paper-remapped` в списках нет: это служебная папка Paper, а не плагин.

**Знает датапаки.** `/datapacks` — только рабочие датапаки сервера (7 штук):
что добавляют в мир, для какой версии, где нужен ресурс-пак. Несовместимые
с 1.21.11 и служебные записи из списка убраны, но в знаниях остались.

**Знает кастомные плагины.** «Разлом» (RiftPlugin: ивент, 19 биомов, 16 боссов,
61 квест, 84 крафта), «Свадьба» (Wedding: команды, помолвка, свадьба, брак,
префиксы, хранилище) и «Скорбь» (Sorrow: измерение-лабиринт). Ответы — по
документации и коду плагинов.

**Понимает античит.** Знает про установленный на сервере античит Eva: проверки X-Ray,
ESP, чит-клиентов и автокликеров, окно согласия при входе, эскалацию предупреждений и
отчёты администрации в Telegram. Объяснит игроку, почему его проверили или кикнули, и как
оспорить через заявку.

**Крафты.** `/craft поршень` — рецепт и схема сетки. В базе 155+ ванильных рецептов
(сверены с данными сервера Paper 1.21.11) и все 84 крафта Разлома.

**Плавная печать.** Ответ появляется и дописывается по мере генерации — текст
выходит постепенно, как будто Ева печатает в реальном времени. Настраивается
в `.env` (`TYPE_ANIMATION`, `TYPE_CPS`, `TYPE_INTERVAL` и т.д.).

**Говорит на любом языке.** Отвечает на языке вопроса, одним языком до конца.
Без эмодзи, значков и разметки — обычной живой речью.

**Следит за порядком.** Отмечает оскорбления в адрес игроков на 68 языках и
письменностях, включая обходы (латиница, цифры и символы вместо букв, растяжки,
разделители). Мат и брань без адресата не считаются нарушением. Карточка о
нарушении приходит только администрации в личку.

**Заявки на помощь.** Кнопка «Нужна помощь» (или `/zayavka`): игрок выбирает
категорию, по шагам описывает проблему (ник, что случилось, когда, что пробовал,
скриншот или ссылка), заявка с номером уходит владельцу и помощнику карточкой с
кнопками «Взять в работу», «Ответить», «Закрыть», «Профиль игрока». Ответ приходит
игроку в личку, статус виден по `/moi`. Открытая заявка одна — следующее сообщение
дописывается к ней.

**Анкеты, жалобы, рассылка, консоль.** Анкета на вступление с кнопками «Принять в
вайтлист»/«Отклонить», жалоба на игрока, рассылка по чатам `/рассылка` (панель,
получатели, пауза, тихий режим, закреп, кнопка-ссылка, прогресс, история),
консоль сервера `/console` через RCON/агент/файл/панель/шелл.

**Песни и поиск.** `/song <название>` присылает mp3-файлом (yt-dlp + ffmpeg);
`/web <запрос>` и `/video <тема>` — поиск в интернете и видео.

## Запуск

```bash
python3 bot.py                  # обычный запуск
python3 bot.py --loop           # сам перезапускается, если упал (для панелей)
python3 bot.py --selftest       # проверить всё: токен, ИИ-ключ, база, знания, крафты, печать
python3 bot.py --menu           # какие кнопки в меню
python3 bot.py --version        # версия кода
python3 bot.py --kb             # что бот знает о сервере
python3 bot.py --kb разлом      # подробно про запись
```

## Постоянная работа: чтобы Ева всегда была включена

Три уровня защиты уже встроены в код: `bot.py` сам перезапускается при ошибке,
внутренний сторож завершает процесс, если поллинг завис больше 5 минут, а внешние
скрипты поднимают его после убийства/перезагрузки. Выбери свой вариант:

### 1. Хостинг-панель (Pterodactyl, Pelican, bot-hosting и т.п.)

В поле «команда запуска» укажи:

```
bash deploy/panel-start.sh
```

Скрипт держит бота включённым: упал — поднимает через 3 секунды. Ничего больше
настраивать не нужно.

### 2. Linux VPS / сервер

```bash
sudo bash deploy/always-on.sh          # автозапуск при загрузке + автоперезапуск
bash deploy/always-on.sh --status      # проверить, что бот жив и защита на месте
```

Ставится systemd-юнит `mc-bot.service` с `Restart=always` + cron-сторож раз в минуту
(смотрит на `data/heartbeat` — если процесс завис, перезапускает). Без root тоже
работает — через cron.

### 3. Windows

Скачай и установи Python 3.10+ с python.org (при установке отметь «Add to PATH»),
затем:

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\install-autostart.ps1
```

Создастся задача в Планировщике: Ева стартует при входе в Windows и перезапускается
при падении. Вручную: двойной щелчок по `deploy\windows\start-eva.bat`.

Важно: на Windows бот будет работать, пока компьютер включён и пользователь вошёл
в систему. Бот сам не даёт системе уйти в сон (`KEEP_AWAKE=on`, экран может
гаснуть), занимает ~60–100 МБ памяти и почти не грузит процессор.

### 4. Docker (любой хостинг с Docker/Procfile)

```bash
docker build -t eva-bot .
docker run -d --name eva --restart always \
    -e RM_AI_BOT_TOKEN=... -e RM_AI_DEEPSEEK_KEY=... \
    -v eva-data:/data eva-bot
```

### Где взять бесплатный сервер 24/7

Ева почти не нагружает машину: ~50–100 МБ памяти, один процесс. Варианты:

- **Проще всего** — поставить рядом с Minecraft-сервером, если у хостинга есть
  консоль/панель (тот же тариф, доплачивать не нужно). Команда запуска —
  `bash deploy/panel-start.sh`.
- **Oracle Cloud Always Free** — бесплатный навсегда ARM-сервер (Ampere, до 4 ядер
  и 24 ГБ памяти). Для регистрации нужна банковская карта (списание ~1$ для
  проверки, потом возврат); карты РФ часто не проходят.
- **Google Cloud Always Free** — бесплатная e2-micro (1 ГБ памяти) в одном из
  регионов США; тоже нужна карта.
- Остальные «бесплатные» тарифы (Railway, Render, Koyeb, Replit) обычно дают только
  пробный период или усыпляют процесс — для круглосуточного бота не подходят.
- Если нашёл любой другой бесплатный VPS — подойдёт инструкция «Linux VPS» или
  «Docker».

## Настройки

Секреты лежат в `.env` рядом с `bot.py` (файл не публикуется). Переменные окружения
важнее файла.

| Переменная | Что задаёт |
| --- | --- |
| `RM_AI_BOT_TOKEN` | токен бота Telegram |
| `RM_AI_DEEPSEEK_KEY` | ключ ИИ (DeepSeek) |
| `RM_AI_MODEL`, `RM_AI_URL` | модель и адрес ИИ |
| `SUPER_ADMIN` | id владельца (получает заявки и отчёты) |
| `HELP_ADMINS` | кому приходят заявки на помощь |
| `BROADCAST_ADMINS` | кому доступна рассылка |
| `HELP_DUP_HOURS` | сколько часов одна открытая заявка на игрока |
| `MC_SERVERS` | адреса Java для проверки статуса, через запятую |
| `MC_BEDROCK` | адрес Bedrock |
| `GROUP_COOLDOWN` | пауза между вопросами одного игрока, сек |
| `AI_MAX_TOKENS`, `AI_TEMPERATURE`, `AI_TIMEOUT` | параметры ответов ИИ |
| `TYPE_ANIMATION` | плавная печать: `on`/`off` |
| `TYPE_CPS` | скорость печати, символов в секунду (личка) |
| `TYPE_INTERVAL` | пауза между правками сообщения, сек |
| `TYPE_GROUP_CPS`, `TYPE_GROUP_INTERVAL` | то же для групп (реже, чтобы не флудить) |
| `TYPE_MAX_SEC`, `TYPE_MIN_CHARS` | предельная длительность печати и минимум символов |
| `POLL_STUCK_SEC` | через сколько секунд зависания бот сам перезапускается |
| `LOG_FILE` | путь к файлу лога (если задан — бот пишет лог туда, UTF-8) |
| `KEEP_AWAKE` | на Windows не давать компьютеру уснуть, пока бот работает |

### Админ-панель

`/admin` открывает панель, доступную только администрации (в личке с ботом).
Кнопки панели: «Админы» (список, ❌ убрать, ➕ добавить), «Статистика»,
«Консоль» (быстрые команды list / eva online / say / time), «Античит»,
«Статус сервера», «Обновить», «Закрыть». Кнопка «🛠 Админ-панель» также
появляется в главном меню у админов.

Доступ к панели и управляющим командам есть только у владельца (`SUPER_ADMIN`,
id `6343943842`). Списки `HELP_ADMINS`, `BROADCAST_ADMINS` и `BOT_ADMINS` тоже
сведены к владельцу. Уведомления античита Eva приходят только владельцу.

Добавлять и убирать админов может только владелец (`SUPER_ADMIN`):
`/addadmin @username`, `/addadmin 123456789` или ответом на сообщение человека.
Список админов сохраняется в файле на диске игрового сервера
(`/bot-data/admins.json`, через API панели), поэтому не пропадает при
перезапуске облака.

### Рассылка по чатам

`/рассылка` или `/bc` — панель настройки: текст или фото, список получателей,
пауза, тихий режим, закреп, превью ссылок, кнопка-ссылка, предпросмотр, прогресс
со стопом и отчёт. Доступ только владельцу и доверенному id (`BROADCAST_ADMINS`).

### Консоль сервера

```
/console list                  команда на сервер
/rcon test                     проверить связь
/rcon set <адрес> <порт> <пароль>
/rcon agent <хост> <порт> <токен>        канал через javaagent
/rcon agent file <папка сервера>         файловый канал
/rcon panel <url> <ключ> <uuid>          панель хостинга
/rcon shell on|off                       шелл хоста
/wl add <ник>, /wl remove <ник>          вайтлист
```
Каналы консоли (пробуются по очереди): **RCON** → **агент в JVM** → **панель
хостинга** → **шелл хоста**. Если хостинг не выдаёт RCON-порт наружу, задайте
в окружении PANEL_URL, PANEL_KEY (клиентский API-ключ Pterodactyl) и
PANEL_SERVER (UUID сервера) — бот будет отдавать команды через API панели,
а ответ читать из logs/latest.log.

### Античит Eva

Античит **Eva 1.1.1** установлен на сервере. Окно согласия показывается только Java-игрокам
с клиентом 1.21.6+; Bedrock (Geyser/Floodgate) и старые клиенты проверяются без окна и не кикаются.

Плагин **Eva** присылает все данные о проверках боту в Telegram (только админам из
`SUPER_ADMIN`/`HELP_ADMINS`). Команды бота работают через RCON-консоль сервера:

```
/eva check <ник>               флаги, риск, клиент, история флагов
/eva report <ник>              отправить все данные игрока боту «Ева» в Telegram
/eva toggle xray|esp|xray-heuristic|client-mods|autoclicker   вкл/выкл проверку
/eva setban <ник> <причина>    ручной бан через консоль сервера
/eva reload                    перечитать конфиг плагина Eva
/eva bot test                  проверить связь плагина Eva с ботом
/eva online                    кто сейчас на сервере
```

Если не работает — проверь связь: `/rcon test`. Пароль RCON в чате не хранится:
бот удаляет сообщение с `/rcon pass`/`/rcon set`.

## Знания о сервере

Всё, что Ева знает о плагинах, датапаках и кастомных механиках, лежит в папке
`knowledge/` обычными markdown-файлами. Формат — в `knowledge/_FORMAT.md`:

```
## Название плагина
ключи: плагин, телепорт, tpa, warp, дом
кратко: телепорты: /tpa, /warp, /home
Что делает, зачем нужен, какие команды у игрока и админа...
```

Что есть сейчас:

- `plugins.md` — 31 плагин (11 показываются игрокам в `/plugins`, остальные
  помечены `видно: нет` как служебные/админские — но остаются в знаниях);
- `datapacks.md` — 11 датапаков (7 рабочих показываются в `/datapacks`,
  несовместимые и обзор помечены `видно: нет`);
- `rift.md` + `rift_crafts.json` — «Разлом»: ивент, биомы, боссы, квесты, 84 крафта;
- `wedding.md` — «Свадьба»: команды, помолвка, свадьба, брак, префиксы, хранилище;
- `sorrow.md` — «Скорбь»: измерение-лабиринт, вход и выход, механики.

Запись скрывается из игровых списков строкой `видно: нет` сразу после `кратко:` —
так в `/plugins` и `/datapacks` попадает только то, чем пользуются игроки.

Файлы можно править на хостинге без перезапуска: `/kb reload` в личке с ботом
(только администрация). Бот подмешивает нужные записи в контекст ИИ по ключевым
словам вопроса — поэтому он отвечает по документации, а не выдумывает.

## Модерация: только оскорбления

Фильтр отмечает **оскорбления**, а не мат. Отмечается: прямое оскорбление человека
на любом языке; грубые слова с двойным смыслом — только в адрес человека;
требования и пожелания («заткнись», «проваливай»); обходы написания (латиница,
цифры и символы вместо букв, растяжки, разделители, смешанные письменности).

Не считается нарушением: мат и брань без адресата, цифры и координаты, ники и
@упоминания, ссылки и домены, обычные слова (мандарин, педикюр, «крыса в подвале»).

Словарь — `app/lexicon.py` (1834 записи, 68 языков), движок — `app/moder.py`.
Вторая линия — проверка ИИ в фоне (отключается `/moder ai off`). Карточка о
нарушении уходит только администрации в личку; в общем чате бот молчит.

## Плавная печать

`app/typer.py`. Telegram не умеет стримить текст, поэтому бот отправляет сообщение
и дописывает его правками: сначала первая часть, дальше — новые порции, пока ответ
генерируется. Если модель уже ответила целиком, печать всё равно доходит до конца
с заданной скоростью. Длинные тексты (>3900 символов) и короткие (<36) уходят сразу.

Настройки в `.env`: `TYPE_ANIMATION=on`, `TYPE_CPS=35` (личка — 35 символов
в секунду), `TYPE_INTERVAL=0.75` (правка раз в 0.75 сек),
`TYPE_GROUP_CPS=60` и `TYPE_GROUP_INTERVAL=3.0` (группы — реже, чтобы не упереться
в лимиты Telegram), `TYPE_MAX_SEC=18` — дольше не тянем. Хочешь быстрее —
увеличь `TYPE_CPS`, медленнее — уменьши.

## Облако: работа без компьютера (Render)

Если нужно, чтобы Ева работала, даже когда ПК выключен, её можно бесплатно
держать на Render (бесплатный веб-сервис). Всё уже готово:

- `Dockerfile` — образ для Render;
- `render.yaml` — blueprint: сервис `eva-bot`, план free, healthcheck `/`;
- бот умеет слушать порт `PORT` (мини-HTTP-сервер с ответом 200) — этого требует
  Render, чтобы считать сервис живым; в ответе видно версию и число запросов;
- **самопинг**: бот раз в 4 минуты запрашивает свой публичный адрес
  (`SELF_PING_URL` или автоматический `RENDER_EXTERNAL_URL`). Для Render это
  входящий HTTP-запрос, поэтому бесплатный сервис не засыпает;
- `.github/workflows/keepalive.yml` — вторая страховка: пинг раз в 5 минут,
  даже если самопинг не сработает.

Порядок (нужен аккаунт Render, бесплатный):

1. Render Dashboard → **New → Blueprint** → выбрать репозиторий `eva-bot`
   (или создать Web Service вручную: Docker, free, healthcheck `/`).
2. В переменных окружения задать `RM_AI_BOT_TOKEN` и `RM_AI_DEEPSEEK_KEY`
   (значения — из `.env`).
3. Дождаться деплоя. Проверка: открыть `https://eva-bot-uulx.onrender.com/` —
   должно быть «Ева работает».
4. В `.github/workflows/keepalive.yml` заменить адрес на свой URL сервиса.
5. Остановить локальную копию на ПК (две копии одновременно конфликтуют за
   сообщения Telegram: одна из них получает 409).

Важно: на бесплатном Render нет постоянного диска — база `bot.db` (заявки,
история) сбрасывается при каждом переразвёртывании. Сами ответы на вопросы
работают всегда: знания лежат в репозитории.

Альтернативы без Render: любой VPS с systemd (`deploy/always-on.sh`) или панель
хостинга (`deploy/panel-start.sh`).

## Диагностика

```bash
python3 bot.py --selftest        # 83 проверки: токен, ключ, база, знания, крафты, печать
python3 bot.py --kb              # какие знания загрузились
tail -f data/bot.log             # живой лог
bash deploy/always-on.sh --status
```

Если бот молчит: проверьте `data/bot.log`, затем `python3 bot.py --selftest`.
Частая причина — другой процесс с тем же токеном (Telegram отдаёт апдейты одному):
`always-on.sh` и `watchdog.sh` сами гасят лишние копии.
