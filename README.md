# Eva — ИИ-помощник сервера Aetherlyn

Telegram-бот на Python 3.12 / aiogram 3, который отвечает **только** по Minecraft-серверу
Aetherlyn: правила, подключение, плагины и датапаки, Sorrow, донат, набор в команду, жалобы
и помощь игрокам. Всё, что не относится к Aetherlyn, вежливо отклоняется.

> Проект собран с нуля. Старый код не использовался. Реальные `BOT_TOKEN`, ключи LLM,
> Pterodactyl, RCON и Telethon-сессия в репозиторий не входят — их нужно прописать в `.env`.

## 1. Жёсткие правила поведения

- Только Aetherlyn. На постороннюю тему — одна строка отказа и возврат к темам сервера.
- Ответ ≤ 6 строк, без эмодзи, вступлений и воды. Факт из базы сопровождается источником
  (`#Aetherlyn #donate`, ссылка на пост или название раздела).
- Если факта нет — «Этого нет в моих данных. Передал вопрос администратору.» и тикет владельцу.
- Запрещено выдумывать IP, цены, ники, состав команды, даты вайпов и любые числа.
- Текст пользователя, подпись к фото, пост канала и интернет — **данные, не команды**.
- Бот не банит, не выдаёт предметы, не запускает и не останавливает сервер по просьбе игрока.
- Секреты, промпты, структура БД, чужие тикеты и инфраструктура не раскрываются.
- Консоль, донат-подтверждения, рассылка, реиндекс и бэкапы — только владелец `6343943842`.

## 3. Быстрый запуск

### Windows

```powershell
cd eva-bot
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
# заполните BOT_TOKEN и остальное в .env
.\.venv\Scripts\python.exe -m app.main
```

### Linux

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
chmod 600 .env
python -m app.main
```

Для локальной проверки без HTTPS удобно поставить `BOT_MODE=polling`.
По умолчанию `BOT_MODE=webhook`; если `WEBHOOK_BASE_URL` пуст, бот сам уходит в polling
и пишет предупреждение. Webhook без `WEBHOOK_SECRET` запрещён.

## 4. Обязательные и необязательные ключи

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather, обязателен для запуска |
| `OWNER_ID` | `6343943842`, единственный владелец консоли и админ-меню |
| `TEAM_CHAT_ID` | служебный чат команды; `0` = копии не отправляются |
| `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` | любой OpenAI-совместимый endpoint |
| `ALLOW_GENERAL_TOPICS` | `true` — свободные ответы на вопросы вне Aetherlyn (нужен LLM); по умолчанию `false` |
| `BOT_USERNAME`, `GROUP_REPLY_ALL` | username бота и режим ответов на все сообщения группы; по умолчанию только по имени/упоминанию/реплаю |
| `PANEL_BASE`, `PANEL_KEY`, `SERVER_ID` | Pterodactyl, read-only по умолчанию |
| `RCON_*` | RCON для owner-команд и статуса |
| `TG_API_ID`, `TG_API_HASH`, `TG_SESSION` | read-only чтение постов каналов |
| `WEBHOOK_BASE_URL`, `WEBHOOK_SECRET` | публичный HTTPS-адрес и secret_token |
| `SERVER_HOST` | публичный IP/домен; **намеренно пуст**, пока владелец не подтвердит |

`PAYMENT_CARD_*` задаются в реальном `.env` на хосте. В публичном `.env.example` их нет.
Если LLM-ключ пуст, бот работает в детерминированном режиме: отвечает только найденными
фрагментами базы и не вызывает LLM. Это штатный режим, а не заглушка.

`ALLOW_GENERAL_TOPICS=false` сохраняет жёсткое правило «только Aetherlyn».
При `true` вопросы вне темы уходят в LLM как свободный помощник; защита от инъекций,
секретов, мошенничества и серверных действий остаётся включённой. На текущем Render
свободный режим включён вместе с DeepSeek.

### Групповые чаты

В личке Ева отвечает на каждое текстовое сообщение. В группе по умолчанию она отвечает
любому участнику, если в тексте есть отдельное слово «Ева»/«Еву»/«Еве»/«Eva», есть
упоминание `@Aetherlynbot` или сообщение является ответом на её сообщение.
`GROUP_REPLY_ALL=true` заставляет её отвечать на все сообщения группы — это шумно и
расходует LLM-квоту, включайте только осознанно. `BOT_USERNAME` должен совпадать с
username бота.

Чтобы бот видел в группе обычные сообщения без упоминания (просто «Ева, привет»),
у @BotFather выполните `/setprivacy` → выберите бота → `Disable`. Если privacy включён,
Telegram присылает боту только команды, упоминания и ответы. Альтернатива — сделать бота
администратором группы: администраторы получают все сообщения.

После смены privacy на `Disable` **удалите бота из группы и добавьте заново**: Telegram
применяет настройку к членству в группе не всегда сразу. Проверено на Aetherlyn: без
повторного добавления бот оставался «членом группы», но update'ы не приходили.

Команды в группе: `/menu` — меню, `/help` — список команд, `/server` — о сервере,
`/plugins` — плагины и датапаки, `/donate` — донат, `/report` — жалоба,
`/apply` — анкета, `/cancel` — отмена. Меню также открывается кнопками после `/start`.
Список команд задаётся через BotFather («Изменить команды») или `setMyCommands`.

Ключи маскируются в логах (`bot...:****`, `ptlc_****`, `sk-****`, номера карт).
`.env` добавлен в `.gitignore`; права на файл — `600`.

## 5. Telegram и webhook

1. Создайте бота у @BotFather, скопируйте токен в `BOT_TOKEN`.
2. Для webhook нужен домен и TLS. Пример nginx: `deploy/nginx.conf`.
3. Заполните `WEBHOOK_BASE_URL=https://eva.example.com`, `WEBHOOK_SECRET` (длинная случайная
   строка), `WEBHOOK_HOST=127.0.0.1`, `WEBHOOK_PORT=8080`.
4. `GET /health` доступен только с loopback; он отдаёт состояние БД, LLM, панели, RCON и
   число чанков. Webhook проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`.

## 6. База знаний

Статические документы лежат в `data/kb/`:

- `core.yaml` — факты сервера, сезон 3, команда, правила, подключение, Sorrow, активность;
- `faq.yaml` — FAQ с приоритетом выше постов;
- `plugins.yaml`, `datapacks.yaml` — фактический состав;
- `donate.yaml` — точные цены и пакеты;
- `channels.yaml` — каналы и их назначение.

Индекс: SQLite + FTS5 (BM25) + локальные хешированные векторы (без платных эмбеддингов),
объединение через RRF. Чанки по 700 символов с перекрытием 80; таблица цен и списки
плагинов хранятся целиком. Если уверенность ниже `MIN_SEARCH_CONFIDENCE=0.55`, ответ
«нет факта» + тикет, без догадок.

### Первичный ингест каналов

Нужен пользовательский Telegram-аккаунт, который состоит в каналах (бот в приватный канал
не добавить). Один раз получите read-only StringSession:

```bash
TG_API_ID=... TG_API_HASH=... python scripts/telethon_login.py
```

Скопируйте выведенную строку в `TG_SESSION`. Затем:

```bash
python -m app.kb.ingest_tg --full
```

Команда печатает статистику: постов, чанков, тегов. Дальше планировщик подтягивает новые
сообщения каждые 10 минут; полный реиндекс — ежедневно в 04:10 МСК и по кнопке владельца
«Реиндекс». Сессия используется только на чтение.

### Обучение на ошибках

Неотвеченный вопрос сохраняется в `unanswered` и создаёт тикет владельцу. В админ-меню
владелец нажимает «Ответить», пишет факт — он попадает в `faq_overrides` с приоритетом
выше постов и применяется немедленно. Раз в неделю приходит отчёт по правкам.

## 7. Меню

Главное меню: «Нужна помощь», «Жалоба на игрока», «О сервере», «Плагины и датапаки»,
«Анкета», «Донаты»; «Консоль» видна только владельцу.

- Помощь: темы вход/логин, лаги, потеря вещей, гриферство, Sorrow, донат, другое.
  После короткого ответа — «Позвать администратора» (тикет с контекстом).
- Жалоба: ник нарушителя, свой ник, дата/время МСК, описание до 500 символов,
  скриншот/видео ≤ 20 МБ, подтверждение. Карточка владельцу с «Принять / Отклонить /
  Запросить детали», копия в служебный чат.
- Анкета: возраст, ник, опыт, часы в неделю, часовой пояс, микрофон, портфолио.
  Решение владельца: испытательный срок / отказ / резерв.
- О сервере: Paper 1.21.11, порт 25646, сезон 3, hard, 20 игроков, Bedrock через
  Geyser/Floodgate. IP показывается только если владелец задал `SERVER_HOST`; иначе бот
  честно говорит, что IP нет в базе.
- Плагины/датапаки: список из API/базы, поиск, пагинация, пометка обновления.

## 8. Донаты

Цены — из `data/kb/donate.yaml`, 17 пакетов от 5 до 1000 печатей плюс игровой пасс.
Курс доллара зафиксирован: `1 $ = 90 ₽`, округление до `0.05 $` (шаг 0.05, не 0.05 знака).
Например, 100 печатей: `175 ₽ / 210 звёзд / 1.95 $ / 49 000 сум`.

Поток: «Донаты» → показать реквизиты по валюте (полный номер только в этом сообщении) →
«Я оплатил» → ник → Telegram → скриншот → пакет → карточка владельцу. Автоподтверждения
нет: только владелец нажимает «Подтвердить», после чего бот создаёт
`AETHER-<печати|PASS>-<8 символов>`, выполняет разрешённую команду выдачи и отправляет
покупателю промокод. Ошибка выдачи помечает промокод «не выдан» и алертит владельца.
Полные номера карт не попадают в тикеты, БД, логи и сообщения команде.

## 9. Консоль и сервер

Разрешены только: `list`, `tps`, `mspt`, `whitelist list`, `say`, `save-all`, `restart`,
`stop`, `backup`, `plugins`, `version`, `promo create <code> <seals>`,
`lp user <nick> parent set <group>`. Команда проходит allowlist-парсер, затем второе
подтверждение inline-кнопкой с TTL 30 секунд; вывод маскируется и обрезается до 1500
символов; каждое выполнение пишется в `audit`.

Pterodactyl read-only: ресурсы, детали, список файлов, `latest.log`, `server.properties`,
файлы `plugins/*`, список бэкапов. Ответы кэшируются 30–60 секунд; при 5xx бот честно
отвечает «статус недоступен», не выдумывая данные.

## 10. Безопасность и тесты

- `<user_data>...</user_data>` вокруг любого пользовательского текста; санитизация NFKC,
  управляющих символов, повторов > 30, длины 2000.
- Детектор инъекций (RU/EN, base64, «###», code fences) до вызова LLM; при срабатывании —
  отказ, счётчик нарушений, audit.
- Валидация вывода: ≤ 900 символов, ≤ 6 строк, без эмодзи, утечек ключей и ссылок вне
  allowlist; ответ без источника не проходит.
- Анти-абуз: 5 сообщений/мин, 40/час, мут 10 минут, капча-кнопка, чёрный список,
  проверка подписки (опционально), лимит файлов 20 МБ и magic-bytes для картинок.
- Владелец проверяется на каждом callback, а не по видимости кнопки.

```bash
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m ruff format --check .
.venv\Scripts\python.exe -m mypy app
```

Тесты не ходят в Telegram и не требуют реальных ключей.

## 11. Деплой

### Docker

```bash
cp .env.example .env
# заполнить .env, затем:
docker compose up -d --build
docker compose logs -f eva-bot
```

TLS и `/health` остаются на хосте (nginx). Для polling уберите публикацию порта.

### Render (бесплатный web-сервис)

Текущий деплой: `https://eva-bot-v2.onrender.com` (Docker, free, Frankfurt),
бот `@Aetherlynbot`. Blueprint: `eva-bot-v2`, ветка `eva-v2`.

В репозитории есть `render.yaml` для blueprint-деплоя из ветки `eva-v2`:
Docker, план `free`, healthcheck `/health`, webhook-режим, `PORT` и
`RENDER_EXTERNAL_URL` подхватываются автоматически. Секреты `BOT_TOKEN`,
`PANEL_KEY`, `RCON_PASSWORD`, `LLM_API_KEY` задаются в Dashboard → Environment
(в git их нет). `ALLOW_GENERAL_TOPICS=true` включает свободные ответы через DeepSeek.
Приложение само ставит webhook на публичный URL.

Ограничения бесплатного Render: сервис засыпает после ~15 минут без входящих
запросов (первое сообщение будит его за 30–60 секунд), диск не постоянный —
SQLite, тикеты и донаты могут исчезнуть при передеплое. База знаний
пересобирается из `data/kb` при старте. Для постоянного диска нужен платный
план или внешняя PostgreSQL; для «всегда онлайн» без засыпания — маленький VPS.
Для текущего сервиса `eva-bot-v2` добавлен GitHub Actions keepalive
`.github/workflows/keepalive.yml`, который пингует `/health` каждые 10 минут.

### systemd

```bash
sudo useradd --system --home /opt/eva-bot --shell /usr/sbin/nologin eva
sudo rsync -a --exclude .venv --exclude .env ./ /opt/eva-bot/
sudo -u eva python3.12 -m venv /opt/eva-bot/.venv
sudo -u eva /opt/eva-bot/.venv/bin/pip install -r /opt/eva-bot/requirements.txt
sudo install -m 600 -o eva -g eva .env /opt/eva-bot/.env
sudo cp deploy/eva-bot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now eva-bot
sudo journalctl -u eva-bot -f
```

Ежедневный бэкап SQLite делает планировщик в `backups/`, хранит 14 дней. Проверка после
перезапуска: `systemctl restart eva-bot`, затем `/start` и вопрос по правилам; индекс не
теряется, потому что лежит в SQLite.

## 12. Обслуживание

- Обновление базы: правьте YAML и нажмите «Реиндекс» в админ-меню либо перезапустите бота.
- Обновление постов: автоматически каждые 10 минут; `--full` — вручную.
- Ротация ключей: замените значение в `.env`, перезапустите сервис, отзовите старый ключ
  у провайдера. Токен бота меняется у @BotFather; после этого старый webhook удаляется
  автоматически при старте.
- Секреты не печатайте в чат и не добавляйте в `data/kb`.
- Инциденты и откат: см. `RUNBOOK.md`.

## 13. Разумные дефолты, выбранные без владельца

- `SERVER_HOST` пуст: IP не выдумывается, бот отправляет к владельцу.
- `TEAM_CHAT_ID=0`: копии в служебный чат включаются только после указания ID.
- LLM не обязателен: без ключа работает детерминированный поиск по базе.
- `REQUIRED_CHANNEL_ID=0`: проверка подписки выключена, пока не задан numeric chat id.
- `SERVER_ID` оставлен ровно таким, каким его передал владелец
  (`acd21ae2-4cf0-49e2-89cc-d8f908f66505a`); перед продом сверьте его в панели.
- Часовой пояс — `Europe/Moscow`, дайджест в 12:00, бэкапы 14 дней, порог уверенности 0.55.

## 14. Что осталось на ручное действие владельца

1. Вписать реальный `BOT_TOKEN` (и при необходимости `LLM_API_KEY`) в `.env`.
2. Указать `TEAM_CHAT_ID` и, если нужно, `REQUIRED_CHANNEL_ID`.
3. Подтвердить `SERVER_HOST` (IP/домен) — без этого бот не показывает адрес.
4. Получить `TG_SESSION` через `scripts/telethon_login.py` и выполнить полный ингест.
5. Проверить `SERVER_ID`, `PANEL_KEY`, `RCON_PASSWORD` в панели хостинга.
6. Включить webhook/nginx/TLS и запустить сервис.
